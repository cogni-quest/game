# Архитектура

**Статус: дизайн согласован, реализация идёт.** Сделано: ядро (задачи,
ответы числом и выбором, попытки, реестр плагинов, разделы и уровни; ответы числом, выбором и
выбором нескольких, указать клетку), 36 плагинов задач, три графа с данными — 41 тема
математики 1–3 класса, 7 тем ветки логики и клеточный диктант в «Памяти и
внимании», — тестовый стенд `apps/play` и первая игра «Детектив». Остальное
в этом документе — план. У каждого правила, где есть причина, причина записана
рядом, чтобы через месяц не пришлось гадать.

Предыдущая версия лежит в `../quest` и **заморожена**. Ребёнок играет в неё,
пока эта не будет готова, потом её адрес перенаправляется сюда. Магазин
игрушек лежит в `../magic-shop` и **не трогается**. Это новый репозиторий, а
не доработка старого: методология спроектирована с нуля, с первого дня
облачная; из старой версии один раз переносятся бой, графика и голос.

## Правила

Действуют для любой части системы, включая ещё не написанные.

1. **Обучение, а не развлечение.** Любая игровая механика движется только
   ответом — никогда ловкостью и никогда таймером. Котик прыгает на следующее
   облачко, потому что ответ верный, а не потому, что вовремя нажата клавиша.
   Ошибка рук — не ошибка в математике, и аналитика бы о ней соврала.
2. **Сложность сама никогда не снижается.** Ни тихого облегчения внутри
   сессии, ни автоматического понижения. Откатить тему может только родитель.
3. **Каждое автоматическое изменение объясняет себя.** Если система открыла
   тему или пометила её, причина сохраняется с цифрами: «освоено: 92% на
   последних 100 задачах за 11 дней, повторение через 7 дней пройдено».
4. **Всё либо настраивается, либо объясняется** — пороги, доли, интервалы
   живут в конфиге, а не в коде.
5. **Ответ — одно простое действие, без точности и скорости рук:** нажатие на
   крупную цель, голос или панель. Формат задачи может быть любым; если он
   просит перетаскивания, оно делается как «нажать — нажать». Перетаскивание,
   рисование, обводка и ползунки — только в режиме «тренировка мага», где
   моторика и есть цель.
6. **Один тип задач = один плагин.** Добавить его — значит создать папку и
   больше ничего не править.
7. **Ядро ничего не знает о монстрах, сердцах, боях и сеттинге.** Оно знает
   задачи, ответы, учебный план, прогресс и монеты.
8. **Только онлайн.** Нет интернета — дружелюбный экран «нет интернета», а не
   полуработающая игра. Распознавание голоса при этом работает в браузере.

## Три слоя

```
┌──────────────────────────────────────────────────────────┐
│  Плагины игр        kings-bounty   (потом: cat-clouds…)  │  как это выглядит и ощущается
├──────────────────────────────────────────────────────────┤
│  Плагины задач      addition  comparing  bonds  maze …   │  что такое один вид задачи
├──────────────────────────────────────────────────────────┤
│  Ядро               граф навыков · программа · выбор ·   │  что спросить и освоено
│                     прогрессия · журнал · монеты         │  ли это
└──────────────────────────────────────────────────────────┘
          │ облачный адаптер             │ голосовой адаптер
       Supabase                       Vosk (в браузере)
```

**Ядро решает, *что* спросить.** Тема, шаг, доля нового и знакомого,
какие повторения пора дать.

**Игра решает, *как* и *сколько*.** «Мне нужно восемь задач, `tier` 5» для
сильного монстра; «одна задача, `tier` 1» для сундука или маленького облачка.
Игра никогда не называет тему.

Зависимости направлены только вниз. Это проверяет `architecture.test.ts`, а
`tsconfig.pure.json` проверяет, что методология не трогает DOM.

## Структура репозитория

Монорепо на npm workspaces: Vite, React,
TypeScript, Vitest.

```
packages/
  core/              методология; без React, без DOM, без Supabase
  tasks/<id>/        одна папка на плагин задачи
    logic/           генератор, регуляторы, проверка ответа — без React
    view/            как рисуется условие — React
  games/<id>/        одна папка на плагин игры (detective; потом kings-bounty)
  voice/             адаптер Vosk, грамматика из описания ответа
  cloud/             адаптер Supabase за портами, объявленными в core
apps/
  play/              сайт ребёнка: `/` — меню игр и «Лавка чудес», `/<игра>` — игра,
                     `/test` и `/admin` — тестовый стенд («Просмотр задач»)
  parent/            экран аналитики для родителей и специалиста
docs/
```

`magic-shop` остаётся в своём репозитории.

## Плагин задачи

Всё, что нужно одному виду задач, в одном месте. Так контракт выглядит в
коде (`packages/core/src/task.ts`):

```ts
interface TaskPlugin<Prompt, Answer extends AnswerSpec<unknown>> {
  id: string                          // 'addition', 'comparing', 'maze'
  /** Ручки приходят данными из графа; плагин проверяет их сам. */
  generate(knobs: unknown, random: Random, weights?: ItemWeights): Task<Prompt, Answer>
  speak(task: Task<Prompt, Answer>): string   // что учитель читает вслух
}

interface Task<Prompt, Answer> {
  pluginId: string
  itemKey: string                     // конкретный пример: '6+7', '13-6'
  prompt: Prompt
  answer: Answer                      // форма ответа и проверка: NumberAnswer, …
}

interface TaskView<Rendered> {        // вид плагина, в view/
  pluginId: string
  renderPrompt(task: Task): Rendered
  renderAnswer?(task: Task, io: AnswerIO): Rendered  // своя форма ответа — поле, где указать
}
```

Плагин пишется через `defineTaskPlugin`: он сам разбирает ручки
(`parseKnobs`, у `addition` — через `zod`) и держит типизированную половину
для своих тестов. `renderAnswer` — своя форма ответа плагина: у диктанта это
поле, где ребёнок раскрашивает путь и указывает клетку; без неё игра берёт общую
форму по виду ответа (панель, кнопки). **Запланировано, ещё не в коде:**
`series()` — серия с вариацией, `<ExplainView>` — модель после ошибки.

**Вся суть — в ручках.** У плагина нет «уровней». Он принимает положение ручек
— у `addition` это `{ operation, kind, second?, minuend?, … }`, — а
**раздел** учебного плана — это одно такое положение. Шаг состоит из форматов,
у каждого формата — свои разделы. Новый раздел или более мелкий шаг — новые
строки данных, а не новый код.

**`itemKey` и `weights` — для трудных примеров.** `itemKey` называет конкретный
пример (`'6+7'`), чтобы аналитика видела, на чём именно ошибки. `weights` —
необязательный перекос на входе генератора: «эти ключи давать чаще». Так ядро
внутри того же шага чаще даёт то, что не получается. Плагин, который не умеет
взвешивать, просто игнорирует `weights`.

**Один пример — несколько отрисовок, и это забота плагина.** `8 + 5` можно
показать цифрами, картинками («8 яблок и ещё 5»), словами («восемь плюс
пять»). Это не разные плагины и не разные форматы графа, а ручка плагина
`presentation` и несколько отрисовок в его `view/`. Плагин сам объявляет, какие
отрисовки умеет и где они уместны (картинки — только до 20); по умолчанию ядро
выдаёт их вперемешку. Граф о них молчит и **переопределяет только при
методической необходимости** — например, «первые разделы новой темы — только
картинками» («предмет → картинка → символ»). Генератор один, ключ примера
общий: аналитика видит, что `8 + 5` трудно *вообще*, а в разрезе по
отрисовкам — что картинками ребёнок решает, а цифрами нет. Голос учителя
(`speak`) тоже зависит от отрисовки. Исключение — **текстовые задачи**: там
другой навык (понять, какое действие нужно), поэтому это свой плагин `word` и
свои темы; генератор чисел он переиспользует общей функцией, а не копией.

**Форму ответа приносит сам плагин.** Центрального списка «разрешённых форм»
нет: если формату задачи нужен свой способ ответа, плагин объявляет его сам —
как проверять, как рисовать, как сказать голосом. Ядро получает только вердикт
и запись для журнала. Общие формы — переиспользуемые кирпичики, чтобы не
писать одно и то же в каждом плагине.

Каталог идей — все под правило 5:

| Форма | Как выглядит | Пример |
|---|---|---|
| `number` | панель или голос | `8+5` |
| `choice` | 2–4 крупные кнопки со словом или картинкой, или голос | лабиринт «какой выход — 1, 2 или 3?», «больше / меньше» |
| выбор нескольких | нажать все подходящие, повторное нажатие снимает | «отметь все чётные» |
| указать | одно нажатие на крупную область картинки | «где на числовой прямой 47?», «нажми лишний предмет» |
| по порядку | нажимать по очереди: первый, второй, третий | «расставь от меньшего к большему» |
| по группам | нажать предмет, потом корзину | «чётные налево, нечётные направо» |
| собрать | кнопки «+десяток», «+единица», «+монета 5» | «собери 47 из палочек», «набери 35 рублей» |
| верно / неверно | две кнопки, только как часть поиска ошибки | «Маша решила 8+5=12 — верно?» |
| два числа | панель с двумя полями | `17÷5 = 3 (ост. 2)` |
| слово голосом | короткий словарь | «круг», «чётное» |

Далёкая идея: камера и настоящие солдатики — «поставь 3 ряда по 4, сколько
всего?».

**Серии с вариацией** (из Teaching for Mastery, «умная практика»): короткая
серия, где меняется одна вещь — `8+2`, `8+3`, `8+4`, `8+5`. Ребёнок видит
закономерность, а не решает четыре отдельных примера, и каждая задача
опирается на предыдущую, которая ещё перед глазами, — это бережёт рабочую
память. Метод необязательный: плагин без серий работает как обычно.

**Модель после ошибки** (оттуда же): после второй неверной попытки, прежде чем
учитель назовёт ответ, плагин может показать модель — десятичную рамку, где
`5` в `8+5` разбивается на `2` и `3`, бар-модель, группы предметов. Ошибка
становится моментом понимания, а не только поражением. Тоже необязательно;
начинать с add-sub-cross-10 (переход через десяток) и mult-meaning (смысл умножения).

**Шаги и их порядок задаёт граф, собранный из учебника,** — не отдельные
правила. Мельче тема режется только по подсказке аналитики, когда ребёнок
застрял. Поверх графа — три проверки качества, они ловят ошибки в коде, а не
навязывают порядок:

- **шаг не выдаёт примеры шага ниже** в том же графе — иначе «новый» шаг
  набирал бы порог старыми примерами; проверяет тест каждого графа. Форматы
  одного шага пересекаться могут, а повторения, «недавно освоенное» и задачи со звёздочкой
  дают старое намеренно — правило про определение шагов, не про смесь;
- **у каждого шага есть хотя бы один формат с ответом числом** — выбор из 2–3
  вариантов угадывается, и порог не должен набираться угадыванием; проверяет
  тест графа;
- **подсказки и нули дозируются**: `7 − 7`, `7 + 0` — настоящие факты, но
  если их много, ответ виден без счёта. Это забота каждого плагина и
  «Просмотра задач» на `/admin`.

## Плагин игры

Так контракт выглядит в коде (`packages/core/src/game.ts`):

```ts
interface GamePlugin<Rendered> {
  id: string;
  title: string;
  subject: SubjectId;      // 'math' | 'logic' | 'attention' — предмет, не тема
  render(host: GameHost<Rendered>): Rendered;
}

interface GameHost<Rendered> {
  requestTasks(r: { count: number; tier: Tier; subject: SubjectId }): Task[];
  submit(task: Task, given: unknown, input: InputSource): Outcome;
  encounterWon(tier: Tier): void;     // монеты платит ядро, по правилу в конфиге
  coinsFor(tier: Tier): number;       // сколько заплатит — чтобы игра показала награду заранее
  loadGameState(gameId: string): unknown;        // прогресс самой игры: что открыто
  saveGameState(gameId: string, state: unknown): void;
  coins(): number;
  onCoins(handler): Unsubscribe;
  renderPrompt(task: Task): Rendered; // рисует любую задачу; игра не знает её типа
  renderAnswer(task: Task, io: AnswerIO): Rendered; // своя форма плагина или общая
  speakTask(task: Task): void;
  speak(text: string): void;
}

type InputSource = 'voice' | 'pad' | 'voice-edited' | 'tap';

interface Outcome {
  verdict: 'correct' | 'wrong';
  final: boolean;          // попыток больше не будет
  showExplain: boolean;    // показать модель после ошибки
  reveal?: Answer;         // назвать верный ответ
  attempt: number;         // 1 — первая попытка; для освоения считается только она
}
```

**Попытки и модель после ошибки — политика ядра,** а не игры: сколько попыток,
когда показать модель, когда назвать ответ. Игра получает решение в `Outcome`
и только рисует последствия — удар, качающееся облачко. Иначе котик и Kings
Bounty сделали бы это по-разному.

**Голос заполняет поле, а не отвечает.**
Распознанное число видно на панели, его можно стереть, отправляет только
кнопка. Ошибка распознавания («тридцать» вместо «тринадцати») видна до
отправки и не стоит ни попытки, ни сердца. В журнал пишется, откуда пришло
число: голос, панель или голос, исправленный на панели.

Игре принадлежат встречи, графика, звук, сюжет и перевод «это сильный монстр»
в уровень. Монеты ей не принадлежат, и она не видит, о чём задача — она
получает компонент, который задачу рисует.

Тоже игре: **тропы, отряды и длина сессии.** Тропа больше не несёт учебный
план — тему решает программа ядра. Тропа — это шаблон уровней
(`1 → 2 → 2 → 3 → 4 → 4 → 5 → босс`), отряд — тоже шаблон (`[2, 3, 3]`), а
монстров на места игра подставляет сама из ростера. Так тропы собираются
автоматически и не кончаются; рукописные тропы и отряды — только по желанию,
ради сюжета, и годятся навсегда, потому что уровни относительные. Мягкий лимит
сессии каждая игра ведёт сама. В Kings Bounty жизни монстров отряда
суммируются — длина боя растёт с отрядом, и это решение
игры.

**Попытки — у шага, если по умолчанию не подходит.** В графе у шага может
быть `attempts`: у клеточного диктанта одна попытка — вторая после промаха была
бы угадыванием по соседним клеткам.

**«Детектив»** (`packages/games/detective`) — первая сделанная игра, предмет
`attention`. Начинается с **доски розыска**: шесть плакатов, по вору на уровень
1–5 и босс, у каждого свой портрет, сила звёздами и награда — ядро платит за
выигранную встречу по её уровню (`DEFAULT_COIN_RULE`: уровень k — k монет,
босс — 10). Ребёнок сам выбирает, кого ловить, среди открытых; сначала открыт
только первый, поимка самого сильного из открытых открывает следующего — иначе
можно было бы бесконечно ловить только слабых. Что открыто, игра хранит через
хост (`loadGameState`/`saveGameState`), а не сама. Одно дело — один вор — одна
задача. Промах — вор убегает, на поле зелёным показан его настоящий путь. Без голоса — по
решению родителя: шаги читаются по стрелкам. На стенде хост временный: шаг
предмета выбирается случайно, монеты — тестового профиля
(`cogni:test-profile:coins`), мост к магазину — шаг 8 порядка работ.

**Kings Bounty** — плагин игры, собранный из старого боя и его графики.
**«Котик прыгает по облачкам»** — эталон второй игры: одна задача на облачко,
верный ответ — прыжок, неверный — облачко качается, а котик ждёт. Чтобы её
добавить, в ядре ничего не меняется.

## Темы, шаги и программа

Три слова, которые легко спутать:

| Слово | Что это | Пример |
|---|---|---|
| **тема** | навык целиком, как его называет учебник; клетка на схеме графа | add-sub-cross-10 «± с переходом через десяток» |
| **шаг** | то, что осваивается за раз; по умолчанию тема — один шаг, мельче её режут только по подсказке аналитики | add-sub-cross-10 |
| **формат** | тип задачи — плагин; у шага их может быть несколько | сложение, вычитание, бар-модель |
| **раздел** | ступень трудности внутри формата, по учебнику | `□ + 2`, `□ + 3` … `□ + 9` |
| **уровень монстра** (`tier`) | насколько трудную смесь задаёт монстр; заодно — сколько разделов брать | 1–5, босс |

- **Граф навыков** — это данные: темы и рёбра «нужно сначала». **Граф — на
  предмет и учебник**: `math-moro.json`, `math-peterson.json`,
  `reading-….json`, `logic.json`, `attention.json`. Программа ребёнка
  собирается из нескольких графов сразу; у каждого предмета в настройках
  ребёнка указано, по какому графу он идёт, и его можно сменить, не трогая
  остальные предметы. Одинаковые темы в разных графах одного предмета имеют
  **одинаковые идентификаторы** — так при смене учебника освоенное
  переносится; темы только из нового графа встают на своё место, темы,
  которых в нём нет, остаются в истории и аналитике, но больше не выдаются.
  Версия для человека — [CURRICULUM.md](CURRICULUM.md).
- **Рёбра и порядок — разные вещи.** Рёбра графа говорят, *что можно*
  открыть: тема открывается, когда освоено всё, на что она опирается. Номер
  темы по учебнику и её класс говорят, *что открыть первым*: из доступных
  тем следующей открывается та, у которой номер меньше. В данных номер — это
  порядок тем в файле графа; тест держит его равным порядку в CURRICULUM.md,
  а зависимости `needs` — подтверждёнными путями по схеме документа. Каждая тема лежит
  внутри одного класса — тема, которая тянется через несколько классов,
  разрезается, иначе её верхний уровень достался бы ребёнку слишком рано.
- **Один бой — один предмет, и предмет выбирает ребёнок — островом.** На
  стартовой карте острова: «Остров чисел», «Остров букв»; ребёнок кликает
  остров, дальше тропы, отряды и боссы как обычно, все задачи — этого
  предмета. Острова — часть игры; ядру она передаёт только `subject`, темы
  внутри предмета по-прежнему решает ядро. Риск — ребёнок будет ходить туда,
  где легче: на старте смотрим по аналитике, сколько он читает, а на `/admin`
  есть кнопка «закрыть остров» на время («сегодня только буквы»).
- **Шаг** технически — одна строка данных: **список форматов**, у каждого —
  плагин и его **разделы** (положения ручек) по возрастанию трудности. По
  умолчанию тема — один шаг. Состояния и пороги — у шагов; тема освоена, когда
  освоены все её шаги.
- **Дополнительные темы и шаги.** Граф наш, а не Моро — в него можно добавить
  то, чего нет в программе (например, «удвоения и почти-удвоения» как
  трамплин к переходу через десяток, или шаг «разложить 5 на 2 и 3» перед
  add-sub-cross-10). По умолчанию такая тема помечена **«дополнительная»**: идёт в
  программе и аналитике как обычная, но **ничего не блокирует** — её можно
  добавить и убрать, не ломая основной путь. Если окажется, что без неё
  дальше никак, её можно сделать обязательной.
- **Форматы одного шага** — разные способы спросить один навык: `8 + 5 = □`
  (Моро), бар-модель (Singapore Math), «Маша решила 8 + 5 = 12 — сколько на
  самом деле?» (Петерсон), `8 + 5 = 8 + 2 + □` (mastery). Ядро выбирает формат
  случайно; освоение считается **по всем форматам вместе**. Иначе на тему
  уходило бы втрое больше времени, а ребёнок учил бы форматы, а не навык. На
  экране родителя точность видна по каждому формату; если один стабильно
  проваливается — подсказка («бар-модель пока непонятна — убрать из add-sub-cross-10 на
  время?»), но не блокировка.

Так шаг записан в `math-moro.json` (сокращённо; `bar-model` — пример
запланированного второго формата):

```json
{ "id": "add-sub-cross-10", "title": "Переход через десяток, до 20", "formats": [
  { "plugin": "addition", "title": "сложение", "sections": [
    { "title": "□ + 2", "knobs": { "operation": "+", "kind": "cross-ten", "second": 2 } },
    { "title": "□ + 3", "knobs": { "operation": "+", "kind": "cross-ten", "second": 3 } }
  ] },
  { "plugin": "bar-model", "title": "бар-модель", "sections": [ … ] }
]}
```
- **Программа** — своя у каждого ребёнка, хранится в облаке: у каждого шага
  есть состояние.

| Состояние | Смысл |
|---|---|
| `locked` | то, на что он опирается, ещё не освоено |
| `introducing` | только что открыт; идёт маленькой, растущей долей |
| `active` | основная часть потока |
| `mastered` | прошёл порог; встречается всё реже, как повторение |
| `flagged` | был освоен, теперь проседает — показывается родителю, и только |

Каждая смена состояния дописывается в журнал изменений с **автором** (`auto`
или `parent`) и **причиной**. Родитель может открыть шаг раньше, закрыть его
или откатить; это такое же изменение, как любое другое, с причиной
«родитель».

### Слои настроек

Настройки складываются слоями; каждый перекрывает предыдущий, но только в том,
что в нём указано:

1. **общий конфиг** — значения по умолчанию;
2. **настройки ребёнка** — «моему нужно больше повторений»;
3. **настройка шага** — «add-sub-cross-10 требует 150 ответов»;
4. **фокус** — временный: «add-sub-cross-10 вдвое чаще до 26 октября». У фокуса всегда есть
   срок, по истечении он снимается сам, иначе через месяц никто не вспомнит,
   почему add-sub-cross-10 выпадает вдвое чаще.

На экране родителя рядом с каждым значением видно, откуда оно («150 — своё для
add-sub-cross-10», «100 — по умолчанию»), любое переопределение снимается одной кнопкой, и
каждое пишется в журнал изменений.

**Кто делает значения по умолчанию.** Регуляторы — код плагина. Шаги (граф
навыков: форматы и их разделы) и общий конфиг — данные в репозитории, с историей
и тестами («каждый шаг генерирует задачи без ошибок», «ни один шаг не выдаёт
задачу шага ниже», «у каждого шага есть формат с ответом числом»). Темы и шаги
— из графа по учебнику ([CURRICULUM.md](CURRICULUM.md)),
пороги и доли — как в этом документе. Переопределения слоёв 2–4 — в облаке,
через экран родителя.

### Стартовая позиция

На старте истории ответов ещё нет. Поэтому:

1. родитель сам отмечает, где ребёнок («bonds-10 … add-sub-2digit освоены, add-sub-2digit-carry активна»);
2. **«испытание»** — проверочный бой по 5–10 задач на каждый отмеченный шаг.
   Уверенно решённое остаётся `mastered`, шаткое сразу становится `flagged`.

Испытание нужно **к переключению**, а не потом: без него шаткое
обнаружилось бы только через две неудачи повторения подряд, то есть через
три с лишним недели.

## Выбор следующей задачи

Выбор берёт программу, `tier`, который запросила игра, повторения, которые
пора дать, и источник случайности с зерном.

### Новое и старое

- **Новый шаг приходит гостем.** Начинает с одной задачи из восьми. Каждый
  день, когда ребёнок решил верно хотя бы ~70% новых задач этого дня, его доля
  растёт ещё на одну. Плохой день замораживает долю, но никогда её не
  уменьшает. За две–четыре недели новый шаг становится основной частью потока.
  **Доля гостя — потолок на весь день**, какие бы уровни ни выбирала игра
  (см. «Уровни считаются от ребёнка»).
- **Старое встречается всё реже, но не пропадает.** Ровно два механизма:
  **недавно освоенное** — шаг `mastered` меньше 21 дня назад (число в
  конфиге), оно идёт в смесь слабых монстров; и **бессрочные повторения** для
  всего освоенного (см. «Прогрессия»). Больше старое ниоткуда не приходит.
- **Повторения подмешиваются, а не выбираются.** Пора — и повторение
  вставляется в обычную встречу; ребёнок никогда не выбирает «повторение», так
  что избегать нечего.
- **Вперемешку, а не блоками.** Вид задачи выбирается заново для каждого
  вопроса.
- **Иногда — серия.** Вместо одиночной задачи ядро может выдать серию с
  вариацией от плагина, в основном на шагах `introducing`. Серия — одна
  связная мысль, а не блок: между сериями всё по-прежнему вперемешку. Как
  часто — в конфиге.

Стартовая доля, прирост доли и срок «недавно освоенного» живут в конфиге.

**Сколько тем одновременно.** Граф — не цепочка: «на сколько больше»,
«цепочки» и «начало умножения» друг от друга не зависят и могут идти
параллельно. Старт — **4 активные темы**: вариативность держит интерес, это
решение родителей. Цена — каждая
тема по календарю идёт медленнее, чем если бы она была одна. Если все активные
идут хорошо (например, ≥ 85% за последнюю неделю) и ребёнок много играет, экран
родителя **подсказывает** добавить ещё одну доступную тему — с кнопкой, не сам:
новая тема — новая нагрузка, а ребёнок бросает, когда тяжело. Максимум — в
конфиге.

### Уровни считаются от ребёнка

Сила монстра — это место на **текущей** лестнице ребёнка, а не фиксированная
сложность. Слабый монстр даёт недавно освоенное, сильный — текущие темы и
больше нового. Когда ребёнок растёт, тот же слабый монстр задаёт примеры
труднее. Поэтому слабые монстры не устаревают, фармить нечего, и ни один
монстр не может перепрыгнуть программу — `100+100` никто не спросит, пока
трёхзначные числа закрыты.

Каждый уровень — смесь состояний программы. Стартовые значения, все в
конфиге:

| Уровень | Недавно освоенное | `active` | `introducing` |
|---|:-:|:-:|:-:|
| 1 | 80% | 20% | — |
| 2 | 50% | 50% | — |
| 3 | 20% | 70% | 10% |
| 4 | 10% | 65% | 25% |
| 5 | — | 60% | 40% |
| босс | — | 70% | 30% |

Задачи со звёздочкой у босса — внутри темы, см. «Уровень внутри шага».

Проценты таблицы — **относительные веса**, а не обещание. Ядро считает,
сколько новых задач уже было за день: пока дневная квота гостя не выбрана,
корзина `introducing` работает по таблице; когда выбрана — корзина пуста. Так
у сильных монстров нового больше, у слабых меньше, но суммарно за день — не
больше, чем разрешает правило гостя, даже если игра даёт одних монстров
5-го уровня. Пустая корзина (квота нового выбрана, в самом начале ещё нечего
считать недавно освоенным, или сейчас не вводится ни одна тема) отдаёт свою
долю `active`, так что пустых встреч не бывает. Давно освоенное (`2+2`, когда
ребёнок уже на двузначных с переходом) не входит ни в один уровень — оно
встречается только как редкое повторение.

### Уровень внутри шага

Уровень монстра решает не только смесь, но и **насколько трудный вариант
того же шага** придёт. Игра просит только «задачу уровня N» — всё остальное
решает ядро:

```
монстр уровня 1 → tier = 1      → смесь уровня 1, и задача — из своей полосы разделов:
                                   add-sub-cross-10 даёт 9 + 2
монстр уровня 5 → tier = 5      → задача из самой трудной полосы: 3 + 9
босс            → tier = 'boss' → трудное, ★ или ★★
```

**Тип задачи и сложность — разные оси.** Тип задачи — это **формат**
(голый пример, картинка, сравнение, числовая прямая): у темы их может быть
несколько, они выпадают вперемешку. Сложность — это **разделы** внутри
формата, только по возрастанию трудности. Разные типы задач никогда не
записываются разделами одного формата: иначе слабый монстр получал бы один
тип, а сильный — другой, хотя один не труднее другого.

**В графе хранятся разделы учебника, уровни считает ядро.** У формата шага —
список **разделов** (`sections`): приёмы темы в порядке учебника, сколько их
там есть, у каждого — положение ручек плагина и источник. Уровней пять, и
**у каждого монстра своё**: разделы делятся на пять полос по порядку, уровень
k даёт только свою полосу — разделы с ⌈(k−1)·N/5⌉+1-го по ⌈k·N/5⌉-й (N — число
разделов). Слабый монстр — только лёгкое, сильный — только трудное, без
разминки снизу. У сложения в add-sub-cross-10 восемь разделов
(`□ + 2` … `□ + 9`):

| Уровень | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 8 разделов | 1–2 | 3–4 | 5 | 6–7 | 8 |
| 5 разделов | 1 | 2 | 3 | 4 | 5 |
| 3 раздела | 1 | 2 | 2 | 3 | 3 |

Когда разделов меньше пяти, соседние уровни их делят. Граф совпадает с
учебником один к одному, сверять и править — дописать или переставить
раздел.

**Босс — трудное и задачи со звёздочкой.** У темы, кроме обычных форматов,
могут быть форматы с пометкой **★** (нестандартные, на смекалку — Петерсон,
«Кенгуру») и **★★** (олимпиадные). Обычные монстры их не получают — только
босс. Задача босса бывает трёх видов, доли в конфиге:

| Вид | Откуда | Доля |
|---|---|---|
| трудная | последний раздел обычного формата | 50% |
| ★ | формат темы с ★ | 35% |
| ★★ | формат темы с ★★ | 15% |

Если у темы нет ★-форматов (или ★★), их доля уходит трудным. Поэтому порядок
разделов в графе решает, что считается трудным, а ★-строки в таблице темы —
что получит босс сверх этого.

**Разделы — из учебника графа (Моро).** Если у темы их мало и не хватает
разнообразия — дополняем разделами из Петерсон или других источников, ставим
по трудности и помечаем источник. Дополнения остаются внутри навыка темы;
нестандартное, «на смекалку», — это ★-форматы, а не разделы.

**На освоение уровни не влияют** — все ответы шага считаются одинаково. Что
ребёнок доходит до трудных вариантов, обеспечивает игра: тропа идёт от
слабых монстров к сильным и заканчивается боссом. Это держится, пока в игре
нет способа бесконечно бить только слабых монстров (свободной арены); если
такой появится — нужно, чтобы часть ответов для освоения была на верхних
уровнях шага.

### Задачи со звёздочкой

★ и ★★ — это **нестандартные задачи по теме**: арифметика знакомая, трудность
в смекалке («Маша 4-я в очереди с начала и 3-я с конца — сколько всего?»), в
духе Петерсон и «Кенгуру». В игре такая задача — мощный удар, шанс, а не
стена; босс побеждается в основном трудными обычными задачами.

Звёздочки — **только по теме, которую ребёнок уже не вводит**: босс даёт ★ и
★★ по темам `active` и освоенным, но не по `introducing` — иначе новое пришло
бы сразу в самом трудном виде и сломало медленное введение.

Ответы на ★ и ★★ пишутся в журнал с ролью `challenge` и **не идут ни в плюс,
ни в минус** освоению шага. Ошибка на задаче, трудной по замыслу, не должна
делать освоенный шаг «проседающим» — иначе ребёнок научится избегать боссов.
У звёздочек свой счёт, как у ветки логики.

## Прогрессия

**Порядок тем — по Моро; темп и повторения — наши**, по принципам mastery
learning и интервальных повторений. По скорости это близко к школе (у Моро
около четырёх недель на тему), только ребёнок никогда не идёт дальше, чем
понял.

Две разные вещи проверяются отдельно: **«можно двигаться дальше»** и **«не
забыл»**. Если их смешать — например, требовать повторение через 30 дней до
открытия следующего, — ни один шаг не освоится быстрее шести недель, и
программа растянется на годы.

**Можно двигаться дальше** — шаг становится `mastered` и открывает то, что на
нём стоит, когда выполнено **всё** из этого. Стартовые значения, все в
конфиге, нарочно строгие — ребёнок медленно усваивает новое и ему нужно много
повторений:

- ≥ 90% верных на последних **100** ответах на этом шаге, во всех его форматах вместе;
- эти ответы приходятся минимум на **10** разных календарных дней (любой день,
  когда по шагу был хотя бы один ответ);
- верное повторение через **7** дней.

**Считается только первая попытка.** Верно со второй попытки — успех для игры
(удар прошёл), но для освоения это ошибка; иначе «90%» ничего не значит.
Остальные попытки пишутся в журнал для аналитики.

Ориентировочно — две–три недели на шаг. Больше игры ускоряет набор 100 ответов,
но не 10 дней и не 7-дневное повторение — и это нарочно: знание, набранное за
один долгий присест, выветривается, размазанное по дням остаётся (эффект
интервалов). Поэтому при активной игре общая скорость растёт за счёт
параллельных тем, а не за счёт одного шага.

**Не забыл** — повторения освоенного идут фоном, пока ребёнок учит новое, и не
кончаются никогда; каждое удачное отодвигает следующее:
`14 → 30 → 60 → 120 → 240 дней → …` Нагрузки почти нет — давний шаг всплывает
пару раз в полгода, — зато ничего не выпадает из памяти незаметно. Неудачное
повторение возвращает интервал к 7 дням; две неудачи подряд — шаг становится
`flagged`. Интервалы — в конфиге.

`unrecognised` (распознавание не поймало слово) не считается никак;
с голосом, который только заполняет поле, до ядра оно
почти не доходит. Время ответа сохраняется, но для освоения **никогда** не
используется: при дизартрии и диспраксии оно измеряет голос и руки, а не
знание.

**Голос против знаний.** На экране родителя точность показывается в разрезе
по способу ввода. Если голосом 78%, а панелью 95% — это проблема
распознавания, а не математики, и подсказка так и скажет.

**Автоматического понижения нет.** Освоенный шаг становится `flagged`, если:

- две неудачи повторения подряд, или
- ниже 75% за последние **30 дней**, если ответов там не меньше 10. Окно по
  времени, а не «последние 20 ответов»: освоенный шаг встречается редко, и
  20 ответов растянулись бы на годы.

`flagged` показывается на экране аналитики и продолжает встречаться как
повторение. Он **не блокирует** шаги, которые на нём стоят: блокировать —
значит откатывать, а это правило 2. Откатить может только родитель.

**Путь назад:** две удачные проверки подряд возвращают `flagged` → `mastered`.

### Что аналитика делает сама, а что подсказывает

- **Сама:** состояния шагов (выше) и **частота трудных примеров внутри
  шага**. Если в add-sub-cross-10 `9 + 4` идёт хорошо, а на `6 + 7` и `7 + 8` ошибки, выбор
  внутри того же шага чаще даёт `6+7` и `7+8`. Шаг тот же, сложность не
  снижается — больше практики того, что не получается.
- **Подсказкой с кнопкой:** разрезать тему на более мелкие шаги, поменять
  порог, включить фокус, добавить параллельную тему. Сама она этого не
  делает: разрезать add-sub-cross-10 и давать только `□ + 2 … □ + 6` — это снижение сложности, пусть
  и умное (правило 2).

```
💡 add-sub-cross-10 «± с переходом через десяток»: 4 недели без прогресса.
   Ошибки: □ + 7, □ + 8, □ + 9 (81% всех ошибок); □ + 2 … □ + 6 — 96% верно.
   Предложение: разрезать на два шага: □ + 2 … □ + 6 → □ + 7 … □ + 9.
   [Применить]  [Отклонить]
```

Применённая подсказка пишется в журнал как «родитель по подсказке».

Потом, когда подсказки экрана аналитики начнут стабильно совпадать с тем, что
сделал бы родитель, те же правила просто начнут применяться сами — вот что на
практике значит «автоматически, с родительским переопределением».

## Журнал

Запись каждого ответа, только дописываемая, — единственный источник правды
для аналитики. Проценты и тренды вычисляются из неё, так что новый вопрос
можно задать всей истории.

**Состояния шагов задним числом не пересчитываются.** Они — события в
журнале изменений, каждое со своей причиной. Новый порог действует только
вперёд; иначе смена порога откатила бы часть шагов, а это правило 2. История
нужна для аналитики и подсказок: «с новым порогом add-sub-2digit сейчас не прошла бы —
проверить?».

| Поле | |
|---|---|
| `at`, `child_id`, `session_id` | когда и кто |
| `game_id` | какой плагин игры |
| `plugin_id`, `step_id`, `knobs` | какой вид задачи, какой шаг, какие ручки |
| `tier`, `level`, `section` | уровень монстра, уровень формата и раздел, из которого пришла задача |
| `item_key` | конкретный пример: `6+7` |
| `role` | `regular`, `review` или `challenge` |
| `task`, `expected`, `given` | сама задача и оба ответа |
| `verdict` | `correct`, `wrong` или `unrecognised` |
| `input` | `voice`, `pad`, `voice-edited` или `tap` |
| `attempt` | номер попытки; для освоения считается только первая |
| `elapsed_ms` | сохраняется, для освоения не используется |

За годы игры — мегабайты.

## Облако: Supabase

Postgres без своего сервера (вход и защита на уровне строк — когда понадобятся). Аналитика — это
SQL-вопросы («точность по шагу за последние десять дней»), а это родная
задача Postgres.

Таблицы, примерно: `children`, `config`,
`program_steps`, `program_changes`, `answers`, `coin_ledger`.

**Пока без входа и ролей.** У ребёнка свой адрес (игра), у родителя — свой
(`…/admin`, экран аналитики), и всё. Осознанный риск: кто узнает адрес
`/admin` или ключ базы из кода страницы, сможет читать и менять данные. Данные
— ответы на задачи и монеты, без имён и диагнозов, поэтому риск пока
приемлем.

**Потом, когда понадобится** (второй родитель, логопед, учитель): вход через
Supabase и роли — `owner` настроил всё, `editor` может менять программу,
`viewer` только смотрит, — правилами на уровне строк в самой базе. Ребёнок и
тогда не вводит пароль: родитель входит один раз на устройстве. Экран
родителя тогда спрашивает свой PIN, даже если игра на этом компьютере уже
вошла.

**Что облако даёт сейчас:** аналитику откуда угодно, удалённую правку
программы, бэкап. **Позже:** доступ для других с ролями, игру на нескольких
устройствах, генерацию задач через LLM.

## Экран родителя (`/admin`)

```
/admin
  ├─ Программа        что ребёнок умеет: темы, шаги, состояния, журнал изменений
  ├─ Аналитика        проценты (в том числе по формату и по способу ввода),
  │                   трудные примеры, подсказки с кнопками
  ├─ Настройки        пороги, фокус, слои, стартовая позиция, закрыть остров
  └─ Просмотр задач   новый формат или шаг — до того, как он попадёт к ребёнку
```

**Просмотр задач.** Выбрать тему, шаг, формат и положение ручек; увидеть
20 примеров ровно так, как их нарисует игра; порешать самому — голосом или
панелью, с моделью после ошибки; если всё хорошо — «включить формат в шаг»
или «открыть шаг». Ответы отсюда в журнал ребёнка не пишутся. Это
обязательная остановка на пути любого нового формата:
`идея → плагин → просмотр задач → включить`. Иначе `0+0`, повтор одного
примера или кривую картинку первым увидел бы ребёнок.

## Монеты и магазин

**Монеты — единственная валюта, и принадлежат они ядру.** Любая игра
показывает монеты как монеты — за них в магазине покупаются настоящие
солдатики, поэтому их нельзя переименовывать под сеттинг, а смена игры никогда
не должна обнулять баланс.

Правила заработка стартуют **такими, как сейчас** (выигранная встреча платит
по её силе: уровень k — k монет, босс — 10, `DEFAULT_COIN_RULE`) и
пересматриваются после запуска. Целевой темп — одна-две игрушки
в неделю.

**Магазин не трогаем.** Сейчас он делит с игрой `localStorage` браузера на
одном источнике: игра пишет заработанные монеты, магазин пишет потраченное.
Поэтому новая игра:

- работает **на том же домене**, что и магазин (`/magic-shop/`);
- зеркалит заработанное в `localStorage` в старом формате;
- читает траты магазина из `magicshop:ledger` и записывает их в облако.

**Мост сделан** (`apps/play/src/wallet.ts`; облака пока нет). Баланс везде
один и считается так же, как в магазине: `quest:profile.gold −
magicshop:ledger.spent`. Выигрыш новой игры дописывается в
`quest:profile.gold` — единственное место, откуда магазин берёт заработанное;
остальной профиль старой игры не трогается, а чужую версию профиля мост не
перезаписывает. Свой итог заработанного — в `cogni:wallet:paid`.
**Собранный сайт** (то, что открывает ребёнок) играет на настоящие монеты,
**dev-сервер** — на тестовом профиле (`cogni:test-profile:*`). Ограничение
старой игры: она читает профиль один раз при открытии и пишет его целиком после
боя, поэтому монеты новой игры теряются, если в это время открыта вкладка
старой. После переключения старый адрес перенаправляется сюда — и проблемы нет.

## Как дойти до переключения

Пока идёт разработка, новая версия использует свой **тестовый профиль** — она
никогда не трогает настоящие монеты ребёнка.

**Переключаемся, когда** новая версия умеет всё, чем ребёнок реально
пользуется сегодня — бой с голосом и панелью, все текущие типы задач как
плагины, арену или её замену, монеты и магазин, — и родитель неделю играл в
неё, не наткнувшись ни на что блокирующее. Тогда монеты и уже купленные
игрушки переносятся, родитель отмечает стартовую позицию, ребёнок проходит
«испытание», а старый адрес перенаправляется. Аналитика, прогрессия и
ветка логики могут приехать после этого.

### Порядок работ

1. ✅ Эти документы.
2. ✅ Каркас монорепо: контракты ядра, интерфейс плагина, один плагин
   (`addition`) как образец и архитектурные тесты.
3. Остальные типы задач как плагины — по графу, в порядке Моро.
4. Плагин игры Kings Bounty из старого боя и графики, с голосом.
5. Supabase: журнал, программа.
6. Выбор задач и прогрессия, с причиной у каждого изменения.
7. Экран аналитики для родителя.
8. Монеты, мост к магазину (✅ мост), хостинг на домене магазина.
9. Стартовая позиция и «испытание».
10. Переключение.

Дальше: ветка логики, тренировка мага, вторая игра, больше устройств.

## AI — идеи на будущее

Почти везде AI — ещё один плагин или адаптер; ядро остаётся простым и
предсказуемым.

- **Работа на бумаге, проверка по фото.** Клеточный диктант карандашом в
  тетради → фото → модель со зрением проверяет рисунок и показывает, где
  сбился («после 5-го хода ушёл влево»). Моторика тренируется по-настоящему,
  как в школе, — идеальное содержание для тренировки мага. Так же — примеры в
  столбик, прописи, школьная домашка. Распознавание фото не 100%: результат —
  подсказка, а не вердикт, и в порог освоения не идёт.
- **Задачи и тексты.** Текстовые задачи про его мир («у короля было 47
  рыцарей…»): LLM пишет только историю, числа и ответ даёт генератор. Тексты
  для чтения нужного уровня и вопросы на понимание. Картинки к задачам.
  Генерируется заранее пачками и проходит «Просмотр задач», а не на лету в
  бою.
- **Разбор ошибок и уроки.** Понять, какая именно ошибка (`47 + 28 = 65` —
  забыт перенос; `13 − 6 = 3` — вычел наоборот): многое решают правила, LLM
  называет по-человечески. Урок, подстроенный под ошибки этого ребёнка.
- **Аналитика для родителя.** Недельная сводка обычным языком; вопросы к
  журналу («почему он стал хуже в вычитании?»).
- **Голос.** Нейросетевой голос учителя (Silero и подобные). Далеко:
  распознавание, дообученное на его голосе, — при дизартрии может дать больше
  всего, но и сложнее всего.
- **Камера и солдатики.** «Поставь 3 ряда по 4» — модель считает фигурки на
  фото: умножение на настоящих предметах.
- ⭐ **Новые юниты, сгенерированные AI.** Интерес держится на новых юнитах, а
  King's Bounty кончается: генерация картинок делает своих монстров в похожем
  стиле. Ребёнок может сам заказать следующего («хочу огненного кота») —
  награда за освоенную тему.
- **Сюжет недели.** Короткая история похода и реплики монстров и учителя под
  темы, которые он сейчас учит.
- ⭐ **Чтение-караоке.** Учитель читает текст задачи, слова подсвечиваются по
  слогам (`ма-ши-на`): текстовые задачи перестают быть стеной при трудностях
  с чтением, и заодно идёт тренировка чтения.
- **Подсказки-лесенки вместо ответа.** «Сколько восьмёрке до десяти?» → «а
  сколько осталось от пятёрки?» — ребёнок доходит до ответа сам.
- **Упрощение текста под его уровень.** Та же математика, меньше чтения.
- **Распечатки для тетради.** Генератор делает PDF с примерами и диктантами,
  фото проверяет AI — круг «экран → бумага → экран».
- **Модель забывания для каждого примера.** Вместо фиксированных интервалов —
  алгоритм вроде FSRS, который по журналу предсказывает, когда ребёнок забудет
  конкретный `7+8`, и даёт повтор ровно перед этим. Не LLM, а обычное
  машинное обучение.
- ⭐ **Признаки усталости.** Ошибки подряд, паузы растут, больше стираний на
  панели — игра предлагает перерыв, на `/admin` видно «устаёт после 12
  минут». Сложность не снижается (правило 2), просто вовремя остановиться.
- **Отчёт для учителя или логопеда** — раз в месяц страница «что умеет, где
  трудности».
- **Идеи на офлайн для родителя** — «на этой неделе add-sub-cross-10: поиграйте в магазин,
  сколько сдачи с 15, если купили за 8?».
- **Фото страницы учебника → черновик плагина** — работа в Claude Code, без
  инфраструктуры.
- **Осторожно:** свободный разговор ребёнка с AI-учителем — непредсказуемо, а
  при дизартрии распознавание хуже; только выбор из готовых вариантов.
  Логопедические упражнения — работа специалиста, AI может ему помогать, но не
  заменять.

**Правила, если будем делать:**

- числа и правильные ответы — всегда код, не AI;
- AI подсказывает, решает человек или правило;
- на фото — только тетрадь или стол, без лица ребёнка;
- облачные модели платные и не мгновенные: генерировать заранее, не посреди
  боя.

## Нарочно оставлено открытым

- **Экономика.** Остаётся как есть, пока нет реальных данных о темпе (цель —
  одна-две игрушки в неделю). Известный риск: плата за объём подталкивает
  фармить лёгкое — относительные уровни монстров частично закрывают это сами.
- **Числительные больше 100 — сделать до тем numbers-1000/add-sub-1000.** Не блокер: голос
  только заполняет поле, панель всегда на экране, так что трёхзначный ответ
  можно набрать. Нужно: расширить числительные до 1000 (код с тестами) и
  проверить распознавание на ребёнке — в грамматике 0–1000 много похожих на
  слух чисел («сто тринадцать» и «сто тридцать»). Если голос справляется
  плохо, в этих шагах ответ идёт в основном через панель — аналитика по
  способу ввода это покажет. Не срочно: это 3 класс, а таблица умножения
  укладывается в 100 (9 × 9 = 81).
- **Голос.** Переносится как есть: распознавание — Vosk с грамматикой (она и
  делает речь ребёнка распознаваемой), конец речи — по таймерам тишины,
  учитель — системный синтезатор. **Потестировать Silero:** Silero VAD (MIT,
  ~2 МБ, в браузере) вместо таймеров для конца речи; Silero TTS (русские
  голоса, бесплатно для некоммерческого) для голоса учителя.
  Сравнивать на ребёнке, отдельным шагом.
- **Уроки — кто объясняет новое.** Сейчас никто: новый шаг приходит гостем, и
  ребёнок сразу должен решать; единственное объяснение — модель после ошибки.
  Для ребёнка, который медленно усваивает новое и бросает, когда трудно,
  первая встреча с новым через ошибку — плохой сценарий. Варианты: короткий
  урок как необязательная часть плагина (`lesson`: учитель показывает 2–3
  решённых примера с моделью, потом 1–2 задачи «вместе»; показывается при
  первом `introducing`, при `flagged` и по кнопке «напомни, как это»); или
  **отдельные уроки** как свой режим. Урок — не бой: без урона и монет,
  ответы не идут в порог освоения.
- **Третий остров — логика, внимание, память.** Решено: клеточный диктант,
  лабиринты, «найди отличия» и прочее, что не числа и не буквы, живёт на
  отдельном острове. Открыто: название (кандидаты — «Остров магов», «Остров
  загадок», «Остров смекалки», «Башня мудрецов», «Остров чудес») и то, не он
  ли и есть «тренировка мага» — режим, где зарабатываются щиты и свитки
  подсказок (максимум 1 за бой) и где единственно разрешена моторика.
  Рекомендация: да, один остров — «Остров магов». Клеточный диктант —
  стрелками `← ↑ → ↓`, рисование пальцем — только как упражнение на
  моторику. Диктант нужно диктовать — ещё один довод протестировать Silero
  TTS пораньше.
- **Персонаж-учитель, записанный голос, сеттинг** — решим, когда до них
  дойдёт.
